# IPC と資格情報の復旧 E2E

.NET 10 の console から、製品の `Preferences.Save` / source-generated JSON、実 AES-GCM / Windows DPAPI、別プロセスのファイルロックと名前付きパイプを呼びます。既存の資格情報・設定は読みません。

独立した `Preferences` は実アプリの `Instance` と同じく読み込み完了状態にし、`App` と同じ `SetCanModify()` を呼んで保存を許可します。各保存で隔離ファイルの置換を確認し、保存がスキップされた場合を検出します。

事前に列挙した失敗と期待動作:

- 未観測 Task 例外を実際の App ハンドラで処理した後も、同じプロセスのログ出力を継続する。
- 鍵の排他ロック中に設定を読み、2 回保存しても暗号文と元の鍵を保持する。ロック解放後に資格情報が復号できる。
- 追加 HTTP ヘッダーも API キーと同じ暗号化・読込失敗時の保持・復旧・明示消去を通し、Authorization の値を平文保存しない。
- OpenAI / Azure OpenAI / Anthropic / Gemini を実戦略からローカル HTTP サーバーへ接続し、追加・Content-Type ヘッダーと応答を検証する。OpenAI では 429 後の再送にもヘッダーが残ることを確認する。外部 API や実資格情報は使用しない。
- DPAPI または鍵形式の読込失敗で鍵を再生成しない。隔離した元の鍵を戻すと復号できる。
- Windows では、旧版 (`27664f25` の親版) の `File.WriteAllText(file, Convert.ToBase64String(key))` と同じ32バイト鍵を生成し、実 source-generated JSON の API キーと追加ヘッダーを暗号化する。同じディレクトリのステージファイルへの途中書込・置換の I/O 失敗を private 境界へ注入し、原本のバイト不変、キャッシュ破棄後の復号、正常移行と再読込、ステージの清掃、新規鍵生成が既存鍵を上書きしないことを確認する。
- 未復号状態で明示的にキーを空へ変更すると保存値を削除する。旧平文の移行失敗でも平文を保存しない。
- 通常の別プロセスへメッセージを転送できる。ロック取得後にパイプが遅れて起動しても再送で転送できる。
- ロックを保持したプロセスが終了すると同じチャネルがロックを再取得する。パイプ初期化失敗時にはロックを解放する。
- 他プロセスがパイプなしでロックを保持する場合は送信失敗を返し、ロック解放後に復旧する。

```powershell
dotnet run --project tests/Recovery.E2E/Recovery.E2E.csproj -c Release -p:DisableAOT=true
```

全 fixture と検証可能な `result.json` は `bin/Release/net10.0/artifacts/<run-id>/` に保存します。再現・結果の照合用成果物なので保持します。実際の API キーは使用せず、人工的な資格情報のみを保存します。子プロセスは正常終了または `finally` で終了します。

鍵移行の失敗注入は同じプロセスの private メソッド呼出しで行い、再起動相当の確認は鍵キャッシュを破棄して実 JSON を読み直します。電源断・プロセス強制終了の再現は含みません。強制終了時は保護済みステージが残る可能性がありますが、旧鍵を先に削除する経路はありません。

この E2E は GUI 初期化と `App` の終了コードを実行しません。その分岐はビルドとコード確認で検証し、GUI 実測は別途必要です。
